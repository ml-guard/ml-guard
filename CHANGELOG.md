## [0.1.0] - 2026-05-10

First public release.

### Added
- **Pickle scanner** detecting RCE primitives, suspicious modules, and
  PyTorch ZIP wrappers. Catches both protocol ≤ 3 (`GLOBAL`) and protocol ≥ 4
  (`STACK_GLOBAL`) attack patterns.
- **Safetensors scanner** validating the binary header, tensor offsets, and
  flagging trailing executable signatures (ELF/MZ/Mach-O), exfiltration hints
  in `__metadata__`.
- **ONNX scanner** parsing the protobuf wire format directly (no `onnx`
  library dependency). Detects custom-domain operators, suspicious
  `external_data` references (URLs, absolute paths, `..`), and shell-like
  string attributes.
- **Secret scanner** with 14 provider-specific regexes (AWS, GitHub, Slack,
  Stripe, OpenAI, Anthropic, Hugging Face, Google, JWT, PEM private keys)
  plus Shannon entropy fallback. Supports `.env`, YAML/JSON/TOML configs,
  Python source, and Jupyter notebooks (cells + outputs unpacked).
- **CVE scanner** cross-checking pinned dependencies against a local
  SQLite-indexed OSV database. Imports the official PyPI dump
  (`https://osv-vulnerabilities.storage.googleapis.com/PyPI/all.zip`)
  in ~2 seconds, indexes ~19 000 advisories. Deduplicates GHSA + PYSEC
  entries that alias the same CVE.
- **CLI commands**: `scan`, `sbom`, `compliance`, `cve-update`, `cve-info`,
  `list-scanners`.
- **CycloneDX 1.5 SBOM** export with SHA-256 per artifact and findings
  embedded as vulnerabilities.
- **Compliance reporter** producing PDF reports for two standards out of
  the box: EU AI Act (Regulation 2024/1689) and NIST AI RMF 1.0. PDF is
  generated by an in-tree minimal PDF 1.4 writer (no `reportlab`/`fpdf`
  dependency).
- **Configuration via `.ml-guard.yml`**: per-rule severity overrides,
  rule disable, file include/exclude globs, scanner whitelisting,
  `fail-on` defaults. Auto-discovered up the directory tree.
- **GitHub Action** (`ml-guard/scan-action@v1`) for drop-in CI usage.
- **Optional Rust engine** (`ml-guard-engine`) with PyO3 bindings,
  installed via `pip install mlsupplychain[native]`. Falls back to pure-Python
  (using `pickletools.genops`) automatically when not available — same
  rule set, same output.
- **SARIF 2.1.0** output for native GitHub Code Scanning integration.

### Documentation
- `docs/rules.md` — full rule catalog with severities and override examples.
- `docs/pickle-threat-model.md` — explains what we cover and what we don't.
- `docs/performance.md` — real benchmark numbers and design decisions.
- `docs/cve-database.md` — workflow for keeping the OSV DB current.
- `docs/examples/github-workflow.yml` — copy-paste workflow.

### Security notes
- The pickle scanner never executes scanned files; analysis is purely static.
- No network calls in the default code path. The CVE database is downloaded
  by the user via `ml-guard cve-update` (or shipped as a separate
  `ml-guard-osv-data` package — planned).
- All findings have stable `rule_id`s suitable for suppression.
